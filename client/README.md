# Sparrow client code

Sparrow publishes no SDK and commits no generated client. Generate one in your
own project from the OpenAPI spec of the Sparrow version you run: `GET
/openapi.yaml` on the server, the `openapi.yaml` attached to each GitHub
release, or `api/openapi.yaml` at that release's tag. See
[Client libraries](https://sarathsp06.github.io/sparrow/reference/client-libraries/)
for Python, TypeScript and Go examples.

`client/python/` is git-ignored: `make client-python` generates it there for
the e2e suite only.

This directory holds the hand-written exception:

## Signature verification helpers (`verify/`, hand-written)

Standalone, dependency-light sample verifiers for Sparrow's Standard Webhooks delivery
signatures (`v1,` HMAC-SHA256 and `v1a,` Ed25519), meant to be copied or vendored into consumer
projects:

- `verify/python/sparrow_verify.py` -- HMAC is stdlib-only; Ed25519 needs `cryptography`.
- `verify/js/sparrow-verify.ts` -- Node >= 16 or Bun, `node:crypto` only.
- `verify/java/SparrowVerify.java` -- Java 15+, JDK only.
- `verify/kotlin/SparrowVerify.kt` -- JDK 15+, JDK only (independent of the Java file).
- `verify/ruby/sparrow_verify.rb` -- stdlib `openssl` only; accepts Rack-style header names.
- `verify/php/SparrowVerify.php` -- PHP 8.1+, no Composer; Ed25519 uses the bundled `sodium`.
- `verify/rust/sparrow_verify.rs` -- deps: `hmac`, `sha2`, `base64`, `ed25519-dalek`.
- `verify/elixir/sparrow_verify.ex` -- `:crypto` only (OTP 25+).
- Go consumers import `github.com/sarathsp06/sparrow/pkg/signature` instead.

`pkg/signature` (Go) is the authoritative verifier: it is tested against vectors generated by
the server's signer (`pkg/signature/testdata/`). The files here are samples that follow the same
rules and should work. Review one before relying on it.

Framework examples: [Verifying Webhook Signatures](https://sarathsp06.github.io/sparrow/guides/verify-signatures/).
