# Prune Journal

Discoveries that make future pruning faster. Not a work log.

## 2026-08-10 - Dead-code baseline established

**Learning:**
- `deadcode -test ./...` is the effective whole-module gate; golangci-lint's
  `unused` (default config, no `.golangci.yml` in repo) was already clean.
  After removing `GetFunctionDocumentation`, deadcode reports zero
  unreachable functions.
- `pkg/crypto.GenerateKey` looks dead from `./cmd/...` roots but is a
  documented test/dev utility (CHANGELOG: "Documented `GenerateKey` as a
  test/development utility") used by `internal/integration` and
  `internal/webhooks/client` tests. Do not prune.
- Tenant infrastructure is deliberately dormant, not dead — `plan.md`
  "Future Considerations": multi-tenant activation deferred, infrastructure
  retained. Never prune tenant scaffolding.
- `plan.md` Parts 11–16 (DLQ, retention, payload limits, CLI, API rate
  limiting) are queued work — anything they reference is live scaffolding.
- Generated code is everywhere: `proto/`, `client/go/proto/`, `*_otel.go`
  (gowrap). Out of scope for pruning; regenerate via `make generate`.

**Action:**
Start future runs with `deadcode -test ./...`; next candidates are likely
duplication (e.g. the two `ed25519.GenerateKey` call sites in
`webhook_service_registration.go:301` and `:658`) rather than dead code.

## 2026-09-09 - Ed25519 keygen duplication removed

**Learning:**
- The `webhook_service_registration.go` Ed25519 keygen duplication (journal
  2026-08-10) is resolved — extracted to
  `generateEncryptedEd25519Key` in `webhook_service_crypto.go`, which is the
  established home for `WebhookService` crypto helpers (all follow the
  internal `s.crypto == nil || !s.crypto.Enabled()` guard pattern).
- `make fmt` (goimports) reformats pre-existing drift in unrelated files,
  including generated `WebhookServiceInterface_otel.go` — revert those hunks
  after formatting or they bury the real diff. Don't "fix" the drift in a
  prune: the `_otel.go` file is gowrap-generated and regenerating would
  reintroduce it.

**Action:**
Deadcode gate still clean. No remaining known duplication candidates; next
run should look at cognitive-complexity targets (e.g. the update-mask logic
in `updateWebhookConfig`) rather than dead code.
