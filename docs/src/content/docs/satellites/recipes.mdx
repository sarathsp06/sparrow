title: Recipes
description: Adapters as config — turn Sparrow deliveries into Slack, Discord, PagerDuty, ntfy, or ClickHouse payloads with one command.

Recipes are adapters as config. Each recipe is a small YAML file pairing a
destination URL (plus headers) with a `transform_template` — a Go template
that Sparrow renders **server-side, per delivery**, turning the generic event
envelope into the destination's native payload. You get Sparrow's retries,
signing, and delivery tracking for free; no glue service to run.

Apply one with the CLI:

```sh
sparrow use slack \
  --param webhook_url=https://hooks.slack.com/services/T000/B000/XXX \
  --event order.created --event order.refunded \
  --label env=prod
```

`--event` (repeatable) picks which event types the recipe receives; `--label
k=v` adds label filters. Both are apply-time choices, never baked into the
recipe. `--param` supplies the values the recipe declares.

## How it's connected

A recipe never runs anywhere. Applying one is pure API configuration, and the
rendering happens inside the Sparrow server on every delivery:

```
apply time (sparrow use <name>):
  1. load the recipe YAML (built-in name or --file), prompt for params
  2. POST /v1/namespaces/{ns}/webhooks
       url + headers from the recipe, params substituted
  3. PATCH /v1/namespaces/{ns}/subscriptions/{id}
       transform_enabled: true, transform_template: <recipe template>,
       events + label filters from --event/--label

delivery time (inside the server, per delivery):
  event matches subscription
    → webhook worker renders transform_template against the event
      (event_id, event_name, timestamp, attempt, payload)
    → rendered output replaces the envelope as the HTTP body
    → signed, delivered, retried, and audited like any other webhook
```

Two consequences worth knowing:

- **Retries re-render.** A failed delivery retries with the same template;
  `{{.attempt}}` reflects the retry count (PagerDuty's recipe uses the stable
  `{{.event_id}}` as `dedup_key` so retries never open duplicate incidents).
- **Template errors degrade, not drop.** If rendering fails at delivery time,
  the server logs a warning and falls back to the plain envelope rather than
  failing the delivery — which is why you iterate with `sparrow template test`
  before applying.

## Included recipes

### slack

Posts a Block Kit message to a Slack incoming webhook. Param: `webhook_url`.
Delivered body:

```json
{
  "blocks": [
    {"type": "header", "text": {"type": "plain_text", "text": "order.created", "emoji": true}},
    {"type": "section", "fields": [
      {"type": "mrkdwn", "text": "*Event ID:*\nevt_0195c2a1"},
      {"type": "mrkdwn", "text": "*Timestamp:*\n2026-01-02T03:04:05Z"},
      {"type": "mrkdwn", "text": "*Attempt:*\n1"}
    ]},
    {"type": "section", "text": {"type": "mrkdwn", "text": "```{\"amount\":1999,\"order_id\":\"ord_42\"}```"}}
  ]
}
```

### discord

Posts an embed to a Discord channel webhook. Param: `webhook_url`.

```json
{
  "embeds": [
    {
      "title": "order.created",
      "description": "```json\n{\"amount\":1999,\"order_id\":\"ord_42\"}\n```",
      "timestamp": "2026-01-02T03:04:05Z"
    }
  ]
}
```

### ntfy

Pushes a plain-text notification to an ntfy topic. Param: `topic_url`. Title,
priority, and tags travel as static `X-Title`/`X-Priority`/`X-Tags` headers;
the body is raw text:

```text
order.created (event evt_0195c2a1, attempt 1) at 2026-01-02T03:04:05Z

{"amount":1999,"order_id":"ord_42"}
```

### pagerduty

Triggers an alert via the PagerDuty Events API v2 (`/v2/enqueue`). Param:
`routing_key`. The event id becomes the `dedup_key`, so Sparrow's retries
never open duplicate incidents:

```json
{
  "routing_key": "R0UT1NGKEY...",
  "event_action": "trigger",
  "dedup_key": "evt_0195c2a1",
  "payload": {
    "summary": "Sparrow event: order.created",
    "source": "sparrow",
    "severity": "error",
    "timestamp": "2026-01-02T03:04:05Z",
    "custom_details": {"amount": 1999, "order_id": "ord_42"}
  }
}
```

### clickhouse

Inserts each delivery as a row via ClickHouse's HTTP interface
(`INSERT ... FORMAT JSONEachRow`). Params: `base_url`, `table`, `user`,
`password` (sent as `X-ClickHouse-User`/`X-ClickHouse-Key` headers). The
target table needs `event_id`/`event_name`/`timestamp`/`payload` String
columns:

```json
{"event_id": "evt_0195c2a1", "event_name": "order.created", "timestamp": "2026-01-02T03:04:05Z", "payload": "{\"amount\":1999,\"order_id\":\"ord_42\"}"}
```

## Writing your own

A recipe is one file, `satellites/recipes/<name>.yaml`, schema version 1:

```yaml
version: 1
name: myservice                # must match the filename
description: One-line human description
params:                        # values supplied at apply time via --param
  - name: api_url
    prompt: "MyService ingest URL"
    required: true
webhook:
  url: '{{param "api_url"}}'
  headers: {Content-Type: application/json}
subscription:
  transform_template: |
    {"title": {{.event_name | json}}, "body": {{.payload | json}}}
```

`{{param "x"}}` tokens in `webhook.url`, header values, and the template are
replaced by the CLI at apply time via plain string substitution. The
substituted template is registered on the subscription and rendered per
delivery with `.event_id`, `.event_name`, `.timestamp` (RFC3339), `.attempt`,
and `.payload`. Helpers like `json`, `printf`, `upper`, and `ellipsis` are
available — see [template functions](/sparrow/reference/template-functions/).

Two rules keep templates robust:

1. Quote every interpolated value through `json` (e.g. `{{.event_name | json}}`)
   so quotes or newlines in payloads can't corrupt the output.
2. Iterate locally with `sparrow template test` (wraps
   `POST /v1/subscriptions:testTemplate`), which renders a template against an
   event type's sample payload without creating anything.

:::note
Sparrow rejects private-network delivery URLs by default (SSRF guard). To
deliver to a local receiver during development, start the server with
`SPARROW_ALLOW_PRIVATE_NETWORKS=true`.
:::
