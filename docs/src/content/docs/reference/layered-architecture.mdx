An interactive view of how a request moves through Sparrow: the client and
embedded UI call the REST API through middleware, the webhook service holds
the business logic, the store/PostgreSQL repository layer persists state,
River queue workers (`EventWorker`, `WebhookWorker`, `BatchJobWorker`) process
async work, and a signing HTTP client delivers to external endpoints.

See [Architecture Overview](/sparrow/reference/architecture/) for the
narrative event-pipeline walkthrough this diagram complements.
