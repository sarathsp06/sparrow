Sparrow tracks the health of every webhook endpoint using an event-sourced state machine with a 24-hour lookback window.

## Health States

| State | Criteria |
|-------|----------|
| **healthy** | >= 90% success rate (3+ events) |
| **degraded** | < 90% success rate (5+ events) |
| **unhealthy** | 5+ consecutive failures OR < 80% rate (10+ events) |
| **unknown** | No events in the last 24 hours |

## State Transitions

```
unknown → healthy     (>=90% success, 3+ events)
unknown → degraded    (<90% success, 5+ events)
unknown → unhealthy   (5+ consecutive failures OR <80%, 10+ events)

healthy → degraded    (success rate drops <90%)
healthy → unhealthy   (5+ consecutive failures)

degraded → healthy    (success rate recovers >=90%)
degraded → unhealthy  (5+ consecutive failures OR <80%, 10+ events)

unhealthy → degraded  (partial recovery)
unhealthy → healthy   (full recovery >=90%)

any → unknown         (no events in 24h)
```

## Get Webhook Health

<Tabs>
  <TabItem label="Connect-RPC (curl)">
    ```bash
    curl -X POST http://localhost:8080/webhook.HealthService/GetWebhookHealth \
      -H "Content-Type: application/json" \
      -d '{
        "webhookId": "YOUR_WEBHOOK_ID",
        "namespace": "default"
      }'
    ```
  </TabItem>
  <TabItem label="Go (Connect-RPC)">
    ```go
    resp, err := healthClient.GetWebhookHealth(ctx, connect.NewRequest(&pb.GetWebhookHealthRequest{
        WebhookId: webhookID,
        Namespace: "default",
    }))
    fmt.Printf("Health: %s, Success Rate: %.1f%%, Consecutive Failures: %d\n",
        resp.Msg.GetHealthStatus(),
        resp.Msg.GetSuccessRate(),
        resp.Msg.GetConsecutiveFailures())
    ```
  </TabItem>

## List Webhooks by Health

Filter webhooks by their current health status:

```bash
curl -X POST http://localhost:8080/webhook.HealthService/ListWebhooksByHealth \
  -H "Content-Type: application/json" \
  -d '{
    "healthStatus": "unhealthy",
    "namespace": "default"
  }'
```

## Health Summary

Get an aggregate health overview across all webhooks:

```bash
curl -X POST http://localhost:8080/webhook.HealthService/GetHealthSummary \
  -H "Content-Type: application/json" \
  -d '{"namespace": "default"}'
```

Returns counts of webhooks in each health state, overall success rates, and p95 response times.

## How Health Tracking Works

1. Each delivery outcome is recorded as a **health event**
2. Health state is **atomically upserted** (tracks consecutive failures, last success/failure timestamps)
3. Webhook health status is **recalculated and persisted** after each delivery
4. Hourly aggregation computes per-webhook **summaries** (p95 response time, error category breakdown)
